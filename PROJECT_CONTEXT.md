Ты — локальный инженерный агент Codex, работающий непосредственно на моём компьютере с Windows.

Твоя задача — самостоятельно исследовать, спроектировать, реализовать, установить, запустить, протестировать и документировать законченную локальную платформу Qwen3-TTS, которая одновременно интегрируется с:

1. SillyTavern;
2. ComfyUI;
3. любыми другими клиентами, способными использовать OpenAI-compatible TTS API.

Актуальное уточнение реализованной архитектуры: публичные alias `tts-1-ru`, `tts-1-ru-fast` (0.6B) и `tts-1-ru-quality` (1.7B) разрешает `ModelRegistry`; единственный `ModelManager` держит не более одной heavy model и сериализует полный synthesis lifecycle. Обычные legacy/OpenAI-compatible запросы используют backend defaults `stable_russian + full`, а explicit request values имеют приоритет. ComfyUI-ноды остаются лёгкими HTTP-клиентами и могут наследовать model из Server.

Не ограничивайся инструкциями и примерами кода. Выполняй работу внутри открытой папки проекта, запускай команды, устанавливай зависимости в локальное окружение, проводи реальные HTTP-тесты и исправляй обнаруженные ошибки.

==================================================
10. РЕЖИМЫ РЕСУРСОВ
==================================================

Реализуй:

cpu
cuda
cuda_on_demand
auto

CPU:

- один worker;
- ограниченная очередь;
- настраиваемое количество потоков;
- резерв потоков для Windows, ComfyUI и внешней нагрузки.

CUDA:

- модель постоянно находится на GPU;
- перед загрузкой проверяется VRAM;
- используется safety reserve;
- при недостатке VRAM — понятная ошибка или CPU fallback;
- не допускать скрытого давления shared GPU memory.

CUDA on demand:

- API постоянно работает;
- тяжёлый worker создаётся при запросе;
- загружает модель;
- синтезирует аудио;
- завершается;
- освобождение VRAM проверяется фактически.

Auto:

- оценивает свободную VRAM;
- оценивает GPU-процессы;
- оценивает RAM и CPU;
- не вмешивается в другие процессы;
- выбирает безопасный режим;
- записывает причину выбора;
- допускает ручное переопределение.

Конфигурация:

resources:
  mode: auto

  gpu:
    enabled: true
    device: 0
    minimum_free_vram_mb: 2500
    safety_reserve_mb: 750
    reject_shared_memory_pressure: true

  cpu:
    enabled: true
    max_threads: auto
    reserve_threads: 2

  ram:
    safety_reserve_mb: 4096

  external_ai:
    monitor_only: true
    process_names: []
    gpu_reserve_mb: 0
    cpu_reserve_threads: 0
    ram_reserve_mb: 0

13. EMOTION-ROUTER
==================================================

Не выдумывай неподтверждённый instruct-control для Base 0.6B.

Основной способ эмоций:

- несколько референсных профилей одного голоса;
- каждый профиль содержит отдельную эмоциональную подачу;
- router выбирает нужный профиль.

Поддержи:

[voice:neutral]
[voice:soft]
[voice:whisper]
[voice:breathy]
[voice:happy]
[voice:sad]
[voice:angry]
[voice:tense]

Router должен:

1. распознать теги;
2. удалить их из произносимого текста;
3. разбить текст на сегменты;
4. выбрать голосовой профиль;
5. использовать neutral как fallback;
6. синтезировать сегменты;
7. добавить паузы;
8. привести сегменты к одному sample rate;
9. объединить WAV без щелчков;
10. вернуть один аудиофайл.

Без тегов должен работать neutral.

Сохраняй эмоциональные междометия:

- ах;
- ох;
- м-м;
- ха;
- другие произносимые звуки.

  Qwen TTS API;
